## 上一轮的推断，这轮拿秒表验了

上一轮说那 177 秒来自"每个提交起一次 `git log`"。这轮直接测：

| 做法 | 实测 | 说明 |
| --- | --- | --- |
| 单次 `git log -1 --format=%B <sha>` | **54ms** | 取一个提交的正文 |
| × 3121 个提交（`--all`） | **≈168 秒** | 与实测的 177.29 秒基本吻合 |
| 一次 `git log --all --format=%H%x00%B` | **327ms** | 全部正文一把取回 |

差了五百多倍。也就是说，那个用例 177 秒里，绝大部分是在反复启动 git 进程，干的是同一件事。

按这个数，改法很确定：把逐提交调用换成一次批量取，这一个用例会从 177 秒掉到一秒以内，
整片 i–p 的 354 秒大概能少一半。这是 Qwen 侧的 `tools/push_divergence_history.py`，
我不改，坐标和数字都留在这里。

顺带一个测到的边角：`git log --all --oneline` 单次要 1.8 秒，也不太便宜。
